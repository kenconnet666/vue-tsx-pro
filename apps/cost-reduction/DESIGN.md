# 联合降本管理 · 设计规格（正式版）

本文是 `apps/cost-reduction` 正式版前端的设计依据：角色、业务对象、流程、导航、每个页面的布局与交互、统计口径、
要补进组件库的组件与实施顺序。页面照这里做，做完一块对照这里验收；改设计先改这里。

## 0. 依据与取舍

| 资料                                       | 定什么                                                                 | 优先级 |
| ------------------------------------------ | ---------------------------------------------------------------------- | ------ |

## 1. 角色与账号

| 角色                     | 定位       | 在平台上做的事                                                                                  | 不做的事                     |
| ------------------------ | ---------- | ----------------------------------------------------------------------------------------------- | ---------------------------- |
| 供应商（主账号）         | 外部参与方 | 提交建议、认可测算或提异议、评估我方方案（接受 / 不接受）、确认一致意见书——签署类动作只能主账号 | 看别家的数据；改计算公式     |
| 供应商（子账号）         | 外部参与方 | 填报建议草稿、上传附件、看本部门的进展                                                          | 签署类动作                   |
| 成本团队                 | 测算与认定 | 齐全性检查、收益测算与测算版本、内部预审、验证窗结论、收益认定（锁定 A）、储备库维护、参数维护  | 派单、判达标、管进度         |
| PEMO（任务池管理员）     | 计划与调度 | 派单（按产品团队分片）、提级裁决、建任务卡、验证达标判断、商务谈定判断、关闭归档、同意计划调整  | 技术判断、收益测算           |
| 产品团队（一级集成团队） | 技术与执行 | 技术评估、出技术方案、方案设计、验证实施、上传里程碑证据、申请计划调整                          | 出收益结论；直接退回成本团队 |
| 项目团队                 | 决策       | 分级决策：提级事项（渠道二供应商评估不收敛）、重大事项审定                                      | 日常流转                     |
| 商务（采购部）           | 线下洽谈   | 回填商务洽谈结果：谈定金额 B、商务条件、合同编号、差额归因                                      | 改 A                         |
| 财务                     | 公式层     | 维护测算公式（版本冻结）；DMC 审批链的“降本确认”                                                | 参数取值的争议处理           |
| 系统管理员               | 平台配置   | 基础数据、字典、流程配置（节点处理人与时限）、工作日历、分级授权、用户与角色                    | 业务单据                     |

三条线各管一段：成本团队管钱不管进度，PEMO 管进度不管钱，产品团队管干活不管结论；任何角色不能同时“出结论”和“判达标”。
权限在两处生效：前端按角色显示导航与按钮（`can()`），后端（假后端）对每个操作再校验一次。

## 2. 业务对象

| 对象     | 编号                                  | 从哪来                                   | 主要内容                                                                                             |
| -------- | ------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 建议卡   | `JY-年度-序号`                        | 渠道一，供应商提交                       | 最小集九项 + 流转字段（收件箱、认领人、答复时限、评估结论、否决原因、复活条件、协商轮次）            |
| 方案卡   | `FA-年度-序号`                        | 渠道二，PEMO 收需求派单、产品团队编制    | 建议卡字段 + 方案来源、技术方案摘要、影响范围、所需资源、供应商评估意见、不接受理由、一致意见书      |
| 任务卡   | `DJ-完成年度-团队缩写-序号` / `DMC-…` | 建议立项、方案转任务；一期直接新建或导入 | 信息表主表与明细 + 任务管理（主办协办、里程碑、验证窗、收益状态、口径、A/B/D、合同与调价、变更记录） |
| 测算版本 | `V1、V2…`（卡内递增）                 | 成本团队每次出测算                       | 测算人、公式版本、参数快照、假设、结果与口径、与上版差异、供应商异议、逐条回应                       |
| 储备项   | 沿用原卡编号                          | 暂无法实施的建议、终止与关闭回流的任务   | 否决原因（固定选项）、复活条件、件号 / 材料 / 工艺、匹配推送记录                                     |
| 待办     | —                                     | 每次跨岗位流转                           | 流程节点、岗位收件箱、认领人、到达方式（转派 / 退回 / 提级）、时限                                   |
| 合同     | 合同编号                              | 商务回填                                 | 供应商、金额、调价状态（未调价 / 调价中 / 已调价）                                                   |

- 卡与流程：每张建议卡、方案卡、任务卡各有一个流程实例；卡的“当前状态”由流程走到的节点决定（节点的 `meta.status`），
  不单独改状态字段。
- 卡与卡：建议卡“已立项”、方案卡“已转任务”时生成任务卡，字段按 §6.5 的映射带过去，任务卡记住来源编号；
  两条渠道重叠的事项只生成一张任务卡（立项时按件号查重，提示合并）。
- 一期的存量项目没有建议卡、方案卡：Excel 导入或直接新建任务卡，流程从“建任务卡”之后的对应节点开始（迁移）。

## 3. 流程

五个流程定义，放在 `src/domain/workflow/`，格式是组件库的 `ProcessDefinition`（BPMN 子集，后端引擎照它执行）。
时限默认按工作日（工作日历见 §6.13）；节点的处理人与时限可以在“流程配置”里调整，发布新版本后对新发起的生效。

### 3.1 渠道一：供应商建议（`suggestion`）

| 节点             | 泳道                     | 时限               | 处理结果 → 去向                                                                                         | 卡的状态 |
| ---------------- | ------------------------ | ------------------ | ------------------------------------------------------------------------------------------------------- | -------- |
| 填表提交（开始） | 供应商主账号             | —                  | → 齐全性检查                                                                                            | 待受理   |
| 齐全性检查       | 成本团队收件箱           | 2                  | 齐全 → 并行分叉；退回补充（意见必填）→ 补充材料                                                         | 待受理   |
| 补充材料         | 供应商（原提交人）       | —                  | 重新提交 → 齐全性检查；撤回 → 结束（已撤回）                                                            | 已退回   |
| 派单             | PEMO 收件箱              | 2                  | 派单（选产品团队）→ 技术评估                                                                            | 评估中   |
| 技术评估         | 选定产品团队的收件箱     | 15                 | 可行 → 汇合；不可行（否决原因、复活条件必填）→ 终止结束（暂无法实施，进储备库）；退单（原因必填）→ 派单 | 评估中   |
| 收益测算         | 成本团队收件箱           | 10                 | 出测算（V1，测算表单）→ 汇合                                                                            | 评估中   |
| 协商与认可       | 供应商主账号             | 10，超时视为无异议 | 认可 → 锁定 A；提出异议（新依据附件必填）→ 轮次判断                                                     | 协商中   |
| 轮次判断（网关） | —                        | —                  | 异议轮次 ≥ 3 → 提级裁决；否则 → 再测算                                                                  | 协商中   |
| 再测算           | 成本团队（上一版测算人） | 10                 | 出新一版（逐条回应必填）→ 协商与认可                                                                    | 协商中   |
| 提级裁决         | PEMO 收件箱              | 5                  | 裁决（终版金额与说明）→ 锁定 A                                                                          | 协商中   |
| 锁定 A 值        | 成本团队                 | 3                  | 锁定 → 结束（已立项，生成任务卡）                                                                       | 已立项   |

规则：技术评估与收益测算并行启动、不互为前置（评估结论会带进测算的假设）；产品团队退单只能退回 PEMO 重派；
成本团队出新一版时必须逐条说明采纳、未采纳与理由；无新依据的重复异议由成本团队标“不计轮次”；计算公式不可议，
异议只能针对参数取值与用量假设。全过程对供应商可见：当前环节、谁在处理（岗位）、预计何时答复。

### 3.2 渠道二：项目团队方案（`plan`）

| 节点             | 泳道                 | 时限 | 处理结果 → 去向                                                             | 卡的状态     |
| ---------------- | -------------------- | ---- | --------------------------------------------------------------------------- | ------------ |
| 收需求派单       | PEMO                 | 2    | 派单（选产品团队；归属不明由 PEMO 判断后派，不退回）→ 出技术方案            | 待派单       |
| 出技术方案       | 选定产品团队的收件箱 | 15   | 提交方案卡（摘要、影响范围、所需资源必填）→ 内部预审                        | 方案编制中   |
| 内部预审         | 成本团队收件箱       | 10   | 值得做 → 供应商评估；不值得做（否决原因必填）→ 终止结束（已终止，进储备库） | 预审中       |
| 供应商评估       | 供应商主账号         | 15   | 接受 → 确认；不接受（理由必填）→ 轮次判断                                   | 供应商评估中 |
| 轮次判断（网关） | —                    | —    | 不接受次数 ≥ 2 → 项目团队决策；否则 → 出技术方案（退回调整，落到原编制人）  | 供应商评估中 |
| 项目团队决策     | 项目团队收件箱       | 5    | 继续推进 → 确认；终止 → 终止结束                                            | 供应商评估中 |
| 确认             | PEMO                 | 5    | 确认（一致意见书必传）→ 转任务                                              | 待确认       |
| 转任务           | PEMO                 | 3    | 建任务卡 → 结束（已转任务）                                                 | 待确认       |

### 3.3 任务池（`task`）

| 节点         | 泳道                  | 时限      | 处理结果 → 去向                                                              | 任务状态                      |
| ------------ | --------------------- | --------- | ---------------------------------------------------------------------------- | ----------------------------- |
| 建任务卡     | PEMO                  | 3         | 建卡（主办、协办、三个里程碑的计划日期）→ 方案设计                           | 待启动                        |
| 方案设计     | 主办（产品团队）      | 按里程碑  | 方案确定（证据必传）→ 验证实施                                               | 方案设计中                    |
| 验证实施     | 主办 + 供应商（会签） | 按里程碑  | 验证完成（证据必传）→ 验证窗结论                                             | 验证中                        |
| 验证窗结论   | 成本团队收件箱        | 5         | 出结论（起止日期、达标与否、报告必传）→ 验证达标判断                         | 验证中                        |
| 验证达标判断 | PEMO                  | 5         | 达标 → 收益认定；不达标（原因必填）→ 方案设计（唯一的回退）                  | 待认定                        |
| 收益认定     | 成本团队收件箱        | 10        | 认定并锁定 A（协商收敛的终版）→ 商务洽谈；挂账待定（缺的定价依据必填）→ 定价 | 待认定                        |
| 定价         | 成本团队              | —         | 完成定价 → 收益认定                                                          | 挂账待定                      |
| 商务洽谈     | 商务收件箱（线下）    | 60 自然日 | 回填（B、商务条件、合同编号、差额归因）→ 商务谈定判断                        | 已认定 → 商务洽谈中（认领后） |
| 商务谈定判断 | PEMO                  | 3         | 谈定 → 关闭归档；未谈定（原因必填）→ 商务洽谈                                | 商务洽谈中                    |
| 关闭归档     | PEMO                  | 3         | 关闭（三材料齐全才可点）→ 结束（关闭，回流储备库）                           | 已兑现                        |

异常：暂停（原因与恢复条件必填，流程挂起、待办保留但不能处理）、恢复；终止（原因必填，主办确认后生效，进储备库）。
计划调整（延期、改里程碑）走 §3.5，不能自己改日期。状态只进不跳：任务卡上没有“改状态”，只有节点的处理结果。

### 3.4 降 DMC 实施审批（`dmc-implementation`，1013 的审批链）

降 DMC 任务在“方案设计”“验证实施”两段里跑这条审批链，链上的节点就是《DMC 降本实施节点信息表》的实施节点
（策划、ECP 批准、MI 批准、DMC 收益影响评估），完成日期回填到实施节点。

| 节点             | 默认处理人（可配置）                     | 完成形式 |
| ---------------- | ---------------------------------------- | -------- |
| 降本策划         | 总体技术集成团队                         | 实施     |
| ECP 批准         | 起落架液压系统集成团队                   | ECP 批准 |
| MI 批准          | 起落架液压系统集成团队                   | MI 批准  |
| DMC 收益影响评估 | 总体技术集成团队                         | 文件     |
| 供应商收益评估   | 涉及的供应商（并行会签，一家否决即退回） | —        |
| 降本审核         | 总体技术集成团队                         | —        |
| 降本确认         | 财务                                     | —        |

每个节点：通过、驳回（退回上一节点的原处理人，意见必填）、催办（发起人或 PEMO 对当前节点）。

### 3.5 计划调整（`task-change`）

主办提交调整申请（调整项：计划完成、里程碑日期、主办协办；原因必填）→ PEMO 审批（同意 / 不同意）→ 同意后写回任务卡并记变更记录。
涉及金额或构型的重大调整按分级授权表再送项目团队（§6.13）。

## 4. 收件箱

流转以收件箱为单位，线上到岗、线下到人。三个动作：

| 动作 | 含义                         | 落点                     |
| ---- | ---------------------------- | ------------------------ |
| 转派 | 跨岗位流转，不确定具体承办人 | 目标岗位收件箱，等待认领 |
| 退回 | 材料不全或结论不成立         | 原处理人，不进岗位收件箱 |
| 提级 | 争议无法收敛                 | 上级岗位收件箱           |

认领制：岗位成员都能认领、先点先得；认领后从其他人的视图里消失并锁定；认领后可以退回收件箱（原因必填、留痕），
同一人不能再认领同一条；超过 3 个工作日没人认领，进团队负责人的“待指定”，指定即生效，被指定人只能申请改派。

## 6. 页面

通用约定：编号都是链接（去卡的详情）；统计都能点进筛好条件的列表；页签、筛选、页码、排序都在地址里；
列表的金额单位写在分组表头里，一个视图只有一种单位；操作按当前用户的角色与卡的状态显示，做不了的不显示（而不是置灰），
只有“为什么不能做”需要解释时才置灰并写原因（如“关闭三材料缺 1 项”）。

### 6.0 演示身份

顶栏头像菜单列出演示身份（各角色一人，供应商甲主账号与子账号），切换后整页按新身份重新取数；菜单里还有“恢复演示数据”。
接统一身份认证后换成个人信息与退出登录。

### 6.1 工作台（首页，按角色）

| 区域       | 内容                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| 待我处理   | 我的待办条数按环节分组（齐全性检查 3、收益测算 2……），超时的标红；每组点进收件箱（带筛选） |
| 岗位收件箱 | 我所在岗位的待认领条数、超过 2 个工作日没人认领的条数；负责人另有“待指定”                  |
| 我负责的   | 我主办的任务：按计划完成排，超时、7 天内到期标出；产品团队、PEMO 显示                      |
| 我发起的   | 我提交的建议 / 方案 / 申请当前在哪个环节、谁在处理、预计何时答复（供应商、PEMO）           |
| 关注       | 按角色的几个数：PEMO 看超时与可关闭，成本团队看待认定与认定超期，商务看洽谈超 60 天        |
| 快捷入口   | 按角色：提交建议（供应商）、新需求（PEMO）、新建任务 / 导入台账（PEMO）                    |
| 最近通知   | 最新 5 条                                                                                  |

### 6.2 收件箱

左右分栏（可拖动、可收起右栏）：左边列表，右边是选中这条的预览与处理面板。

**页签**：我的待办（认领的、指定给我的、流程直接给我的）｜岗位待认领｜待指定（团队负责人）｜我已处理｜我发起的。

**列表列**（§五要求直接展示）：件号、零件名称、工作包与产品、建议类别、预期收益量级、是否涉构型更改、提出方与提出日期、
环节、到达方式（转派 / 退回 / 提级，色调区分）、来自（节点与人）、剩余工作日（超时标红）、认领人。
查询：关键字（编号、件号、名称）、环节、流程（建议 / 方案 / 任务 / 审批）、到达方式、超时。

**预览面板**：卡的摘要（编号、名称、状态、关键字段）、流程进度（泳道流程图缩略，当前节点高亮，可放大）、
最近流转记录；操作区按这一条与我的关系：

| 我和这一条的关系 | 操作                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------- |
| 岗位待认领       | 认领（先点先得；被别人抢先时提示并刷新）                                                                       |
| 我认领的         | 处理（节点的处理结果按钮，要填的意见、附件、字段在对话框里）、退回收件箱（原因必填）、去卡里处理（表单类节点） |
| 指定给我的       | 处理、申请改派（原因必填）                                                                                     |
| 负责人待指定     | 指定承办人（从岗位成员里选）                                                                                   |
| 我发起的         | 催办（给当前处理人或岗位负责人发通知，每天一次）、撤回（建议在受理前）                                         |

批量：岗位待认领可以批量认领；我的待办可以批量处理同一环节同一结果（只限不需要填写的结果）。

### 6.3 渠道一 · 供应商建议

**建议列表**（内部）：页签按状态（待受理、评估中、协商中、已立项、暂无法实施、已退回、已撤回）；列：编号、件号与零件名称、
供应商、建议类别、预期收益量级、是否涉构型更改、当前环节与处理岗位、剩余工作日、协商轮次、状态、提出日期。
查询：关键字、供应商、建议类别、工作包、型号、提出日期区间、超时。导出所选。

**提交建议**（供应商）：最小集九项——型号、工作包、件号与零件名称（可多条）、建议类别、现状描述、建议方案、
预期收益量级（区间：<10 万、10–50 万、50–200 万、>200 万；DMC 用美元 / FH 的区间）、是否涉构型更改、实施难度（低中高）；
附件可选。子账号保存草稿、提交给主账号；主账号提交（签署确认框写明“提交即表示……”）。提交后不可改，可撤回后修改再提交。

**建议详情**：

| 区域     | 内容                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------- |
| 页头     | 编号、名称、状态、当前环节与处理岗位、预计答复日；按我的角色与当前环节给出操作                                 |
| 流程     | 泳道流程图：节点状态（完成、当前、未到）、走过的连线、退回与提级的虚线；点节点看那一步的处理记录               |
| 建议内容 | 九项与附件；提出方与日期                                                                                       |
| 技术评估 | 结论、否决原因与复活条件、评估人（岗位）与日期                                                                 |
| 收益测算 | 测算版本时间线：V1、V2……每版的金额与口径、测算人、公式版本；选两版对比（参数逐项差异、各影响多少金额、瀑布图） |
| 协商     | 轮次 1–3：供应商的异议（附新依据）与成本团队的逐条回应（采纳 / 不采纳、理由）；不计轮次的异议单独标出          |
| 流转记录 | 时间线：谁、何时、做了什么、意见与附件                                                                         |
| 沟通     | 留言（@ 岗位或人，带附件），不改变流程                                                                         |

**测算表单**（成本团队出 V1 与新一版）：公式版本（当前生效、只读）、参数（自动取参数层当期值，可改取值但要附依据）、
假设（用量、工序、废品率）、结果实时计算；新一版必须对上一版的每条异议写回应。提交后版本冻结。

### 6.4 渠道二 · 项目团队方案

**方案列表**：页签按状态（待派单、方案编制中、预审中、供应商评估中、待确认、已转任务、已终止）；列：编号、名称、
来源（项目团队需求 / 年度评审……）、产品团队、涉及供应商、影响范围、当前环节、剩余工作日、不接受轮次、状态。

**新需求**（PEMO）：需求名称、来源、型号、工作包、涉及件号、期望收益量级、说明、附件；保存即进入“收需求派单”。

**方案详情**：同建议详情的结构，内容换成方案卡：方案摘要、影响范围、所需资源、内部预审意见、供应商评估意见与不接受理由
（逐轮）、一致意见书、项目团队决策。编制环节的产品团队在这里编辑方案卡并提交。

### 6.5 任务池

**任务列表**（两页：单机降本、降 DMC；字段与单位不同，骨架共用）：
页签两组——状态分组（全部、执行中、待认定、商务中、已兑现、已关闭、异常）与关注（超时、7 天内到期、可关闭、关闭材料不全）。
列：编码、名称、来源（渠道与编号）、类别、责任团队、主办、目标（预期）、测算 A、商务 B（分组表头写单位）、收益状态、
当前环节与处理岗位、里程碑（圆点）、计划完成、超时、操作（处理当前环节、更多）。降 DMC 另有实施节点列。
详情行：简要描述、明细摘要、里程碑与证据、关闭三材料。按钮区：新建任务、导入台账（Excel）、导出（全部 / 所选，
按 C919 模板）。勾选后：导出所选、批量催办。

**任务看板**：列是八个状态（异常的单独一列），卡片显示编码、名称、主办、超时；拖到下一列等于处理当前节点（弹出处理对话框），
拖到不允许的列弹回并说明原因。按团队、主办、降本类型筛选。

**任务详情**：

| 区域       | 内容                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| 页头       | 编码、名称、状态、收益状态、当前环节与处理人；操作（处理当前环节、申请计划调整、暂停 / 恢复、终止、编辑信息表、导出） |
| 进度       | 八个状态的步骤条（处理人与时限写在每一步下面），异常状态标在推断的那一步；可展开成泳道流程图                          |
| 概览       | 信息表主表字段（与编辑页同组）、来源卡（链接）                                                                        |
| 明细       | 单机：构型通知单与零件更改（更改前后、费用、收益）；降 DMC：实施节点与审批链进度                                      |
| 里程碑     | 三个里程碑：计划、实际、证据文件（可预览、下载）、提交人                                                              |
| 验证窗     | 起止日期、结论、报告                                                                                                  |
| 收益       | 预期、测算 A（锁定标记与版本）、商务 B、差额 D 与归因、口径、收益状态、合同与调价状态；测算版本可展开                 |
| 关闭材料   | 三项清单，缺的写清由谁出具                                                                                            |
| 流转与变更 | 流转记录、字段变更（谁改了哪些字段、前后值）、沟通留言                                                                |

**新建 / 编辑任务（信息表）**：单机降本、降 DMC 两张表单，字段与校验严格按《降本项目信息表》（主表、明细四段 / 实施节点），
加上任务管理字段（主办、协办、里程碑计划）。系统生成、计算、带出的字段只读（编码、联络人工号、各项费用与收益）。
从建议卡、方案卡生成时预填：名称、型号、工作包、涉及供应商、件号（进明细）、预期收益（→ 单机降本或降 DMC）、
简要描述（现状描述 + 建议方案）、任务类别（建议类别）、任务来源（渠道）。

**Excel 导入导出**（按 C919 模板）：

- 导出：主表一个工作表（“C919 单机降本” / “DMC降本”，列与表头照模板，含第一行标题），明细一个工作表（单机：
  多行合并表头、更改前后与收益；DMC：每个项目的实施节点一行，项目编码合并单元格）。
- 导入：选文件 → 自动识别工作表与表头 → 列对应（模板列名直接对上）→ 逐行校验（信息表的规则，错误定位到单元格）→
  预览（新增几条、更新几条、出错几条）→ 确认导入。模板里一个单元格多个件号用换行分隔：导入时拆成一个件号一条。
- 模板比信息表多出的列（提出区域 / 战区、纳入考核说明，以及 DMC 模板里的任务类别、任务来源、提出部门、经费来源、
  项目建议书编号）作为可选字段收下。

### 6.6 降本明细（1013 的“降本明细管理”）

**零件变更明细**：跨项目，一个件号一行：项目编码、更改类型、更改前件号与更改后件号、材料是否变化、单机数量、
单件材料费 / 工时费 / 零件收益、单机零件收益、工程评估、是否双定点。查询：件号、材料牌号、团队、更改类型、年度。
合计只在同一单位（元）下。导入导出按单机明细模板。

**实施节点明细**：跨项目，一个节点一行：项目编码、名称、完成形式、计划与实际完成、超时、贯彻架次、责任团队、需要 SB。
页签：未完成、已超期、本月到期、已完成。导入导出按 DMC 明细模板。

### 6.7 收益

**收益认定**（成本团队）：页签待认定、已认定、退回、挂账待定；单位分段切换。列：编码、名称、责任团队、验证窗结论、
最新测算版本与金额、协商轮次、剩余工作日（验证完成后 10 个工作日内，超期标红）、操作（认定并锁定 A、挂账待定、退回验证）。
认定对话框写清锁定的金额与版本，确认后不可改。

**商务洽谈**（商务、PEMO）：页签待认领、洽谈中、待谈定判断、已谈定；列：编码、名称、供应商、A、洽谈天数 / 60（超期标红）、
B、差额 D、合同编号。回填对话框：B、商务条件、合同编号、差额归因（固定选项，D ≠ 0 时必填）、谈定记录附件；
D 实时算出。

**一本账**（成本团队）：单位页签；金额口径分段（硬节约、成本规避、软节约）；“截至日期”（默认今天，可选过去的时点：
按变更记录还原那一天的状态，导出与对外材料一致的清单）。四栏机会值、预测值、承诺值、实现值，每项只落在所属一栏，
挂账待定单独一栏写“待定价”；底部只按栏合计。导出 Excel。

**差额分析**：D 的归因结构（金额与件数）、按供应商、按团队、按测算偏差的分布；用于校准测算模型、分析让利结构。

### 6.8 测算

**测算公式**（财务维护，1013 的“计算字典”）：公式列表（名称、适用范围：单机零件 / DMC、版本、生效日期、状态：草稿 / 生效 / 冻结）；
公式详情：表达式（四则运算、变量、少量函数）、变量说明（来自参数层或假设层）、试算（填变量看结果）、版本历史与差异。
发布新版本后旧版本冻结；已出的测算版本记着用的公式版本。

**测算参数**（成本团队，参数层）：材料单价、工时费率、成材率、税率……按版本维护、带生效日期与市场依据附件；
表格里直接编辑（单元格编辑、行校验），保存成新版本；可以从 SAP 物料价格同步（演示期间是按钮 + 假数据）。

### 6.9 储备库

**储备列表**：原编号、名称、件号、材料、工艺、否决原因（公差限制、外观要求、强度要求、成本不划算、需构型更改、
供应商能力不足、其他）、复活条件、来源（暂无法实施 / 终止 / 关闭回流）、入库日期、被匹配次数。
左侧是否决原因的占比（点了筛选），直接看出该改设计规则、验收标准还是成本模型。

**储备详情**：原卡的快照（只读）、否决与复活条件、匹配推送记录；“复活”生成新的建议卡或方案卡（带原编号）。

**匹配推送**：触发事件（新供应商接入、新型号立项、设计规则修订、材料牌号归并）→ 按件号、材料、工艺、否决原因反向匹配 →
推送给对应的成本工程师与设计师（通知 + 收件箱）。页面列出推送记录与处理情况；管理员可以手动触发一次匹配（演示）。

### 6.10 统计分析（1020 的计数纪律 + 1013 的项目统计、金额统计、预期与实际）

**统计看板**：单位页签；需要处理（超时、7 天内到期、待认定、认定超期、可关闭、关闭材料不全）；任务池构成（三桶）；
预测、承诺、实现三张卡；预期与实际（今年按月累计，年度指标是目标线）；推进漏斗（任务池 → 三个里程碑 → 已兑现 → 已关闭）；
进度 × 收益状态矩阵；超时最久的项目；团队 × 进度（点团队进台账）；测算 A → 商务 B（按差额归因的瀑布）；金额口径三栏。数字都能点。

**项目统计**：按年度、团队、类别、渠道的项目数与状态分布，趋势（按月新增、关闭）。
**金额统计**：按收益状态分开的金额（不跨状态合计），按团队、供应商、类别；预期 vs 实际（预测值与实现值按月折线，
目标线是年度降本指标）。
**渠道转化**：建议 → 立项 → 任务 → 兑现的漏斗；各环节平均停留工作日与超时率；否决原因占比。
**考核取数**：按责任一级团队的指标完成（目标、承诺、实现、完成率）、时限达成率；导出（三期：考核数据不再手工填报）。

### 6.11 供应商门户

供应商只看到与自己有关的数据：我的建议（状态、当前环节、处理岗位、预计答复日）、待我确认（认可测算 / 提异议、评估方案、
确认一致意见书，主账号才能签署）、我参与的任务（验证实施会签、里程碑）、通知。子账号能看本部门的建议、填草稿、传附件。

### 6.12 基础数据（外来数据：SAP 主数据与价格、CMOS 计划任务、统一身份认证）

型号与工作包、产品；供应商（主账号、子账号）；组织与人员（单位、部门、责任一级团队、岗位成员、团队负责人、PEMO 分片）；
合同；物料与价格（SAP）；年度计划任务（CMOS，任务卡的“型号计划”从这里选）；字典（任务类别、完成形式、经费来源……）。
从外部同步的只读，页头写最近同步时间；字典可增改停用（已用的值不能删）。关联字段一律引用主数据，不允许自由文本。

### 6.13 系统管理

**流程配置**：五个流程的泳道流程图（只读的结构）；点节点改处理人（岗位、指定人、按变量）、时限、超时规则、提醒；
校验通过才能发布，发布生成新版本，进行中的按原版本走完。
**工作日历**：按年维护节假日与调休（日历视图点选），所有时限按它算。
**分级授权**：按影响金额与是否涉构型分级，各级的审批人与时限（待确认项，先做配置页）。
**提醒规则**：到期前几天提醒、超时后提醒谁、催办频率上限。
**操作日志**：谁、何时、对哪张卡、做了什么（含导入导出），可按人、对象、时间查。
**用户与角色**：演示期间是身份列表；接统一身份认证后维护角色与数据范围。

### 6.14 通知

顶栏铃铛：新到的待办、被退回、被提级、催办、快到期 / 超时、匹配推送、导入完成；按类型分组，标已读，点了去对应的卡或收件箱。

## 7. 统计口径（计数纪律）

- 每个统计视图只有一个任务池总数；两渠道重叠事项只计一次。
- 已确认收益、挂账待定、方案待定三桶互斥，加总等于任务池总数；终止的回流储备库、不计入。
- 机会值、预测值、承诺值、实现值分开挂账，不跨状态合计；同一笔收益只在实现值一栏出现一次。
- 挂账待定金额写“待定价”，不写零也不写估算值。
- 硬节约、成本规避、软节约分栏，不混总数。
- 单机降本（万元）与降 DMC（美元 / FH）单位不同，一个视图只有一种单位。
- 任务进度与计价状态是两个维度，交叉成矩阵，不用“其中”。
- 后端按同一套规则算（`src/domain/ledger`），看板、一本账、导出的数一致。

## 8. 界面规范

- 时限：剩余工作日 `还剩 n 个工作日`，今天到期标黄，超时 `超 n 天` 标红；时限都按工作日历。
- 金额：表格里只写数，单位在表头；详情里带单位；锁定的 A 带锁的图标；没有值写“—”，挂账待定写“待定价”。
- 需要理由的操作（退回、否决、不接受、终止、暂停、退回收件箱、申请改派）在对话框里填，理由必填并留痕。
- 签署类操作（供应商提交、认可、接受、确认一致意见书）确认框写明含义。
- 导出与模板一致；导入有预览与逐行错误，不静默丢数据。
- 列表页正好占满窗口高度：表格里滚动，分页贴着表格；宽屏（约 2000 px）好看第一位。
