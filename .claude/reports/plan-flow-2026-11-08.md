## 核心想法

**一个流程就是一个小 TS 工程**，可视化设计器与代码编辑的是同一份东西：

```
purchase/
  process.json     图：节点、连线、泳道、布局（设计器画的；代码里 import 进来有类型）
  form.ts          单据：zod schema + 字段的界面信息（标签、控件、栏宽、显示与必填条件、计算字段、明细表）
  logic.ts         逻辑：处理人、守卫、条件、自动动作、监听、自定义动作——带类型的 TS 函数
  views/*.tsx      需要时才写：自定义的发起页、审批单的分区、打印页（用组件库的组件）
  test.ts          场景测试：谁发起、谁处理、走到哪、单据变成什么
```

- 类型从头贯到尾：form.ts 的 schema 推出变量类型 → 条件、处理人、动作函数的 `ctx.form` 有类型 → 客户端
  `flow.process(purchase).start({ … })` 写错字段是编译错误 → 审批单的表单由 schema 生成。
- 借用项目已有的代码：宿主登记可以给流程代码用的模块（组件库、zod、业务服务、ORM 实体、字典……），流程代码直接
  `import { Supplier } from '@app/entities'`、`import { pushToErp } from '@app/erp'`；在线编辑器拿到这些模块的类型，有补全和报错。
- 管理员在“流程工作室”里在线编写：文件树、带 TS 语言服务的编辑器、表单实时预览、场景测试一键跑、和上一版对比、发布、回滚。
  发布前类型检查不过不让发；每次发布是一个不可变的版本（所有文件的快照与编译结果），运行中的实例留在自己的版本上，管理员可以把实例迁到新版本。
- 信任模型：只有管理员能写，代码在宿主里直接执行（不做沙箱）；改动有审计记录。

## A. 只认 Postgres，用好 PG

- 去掉 MySQL（CI 任务、mysql2、文档里的说法）与 SQLite（测试改用 PGlite，进程内；CI 另跑 PG 17 容器）。
- 用到的特性（逐项核对 PGlite 也支持）：
  - JSONB 存单据、运行状态、事件数据；按单据字段查待办、做报表走 `->>` / `@>`，GIN 索引；
  - 作业抢占 `FOR UPDATE SKIP LOCKED`，多实例部署不重复执行；
  - 部分索引：开着的待办、到期作业；
  - 递归 CTE：组织树（上级链、部门下的人）；
  - text[] 与 GIN：候选人（C2）；
  - LISTEN / NOTIFY：新待办、超时、单据变化推给在线页面（浏览器演示里 PGlite 同样可用）；
  - advisory lock：同一流程的发布串行；`RETURNING`、`ON CONFLICT`、identity。

## B. 用好 easy-query-ts，缺口补进 ORM 并发版

- 盘点引擎里手写 SQL、绕开 ORM、逐条查询的地方，能换成 ORM 写法的换掉。
- 预计要补（以盘点为准；每项在 easy-query-ts 带测试与文档示例，按它的流程发版，引擎跟进）：数组列（text[] codec、`&&` / `@>` /
  `any`）、行锁 `forUpdate({ skipLocked, nowait })`、带 where 的部分索引与 GIN 索引声明、JSONB 运算的类型安全写法、递归 CTE、
  LISTEN / NOTIFY 的适配器接口（pg 与 PGlite）、advisory lock。
- 引擎的表改走 easy-query-ts 的 code-first 迁移，版本化，服务端升级时自动迁移。

## C. 引擎：比 Java 版更好的设计

1. **动作插件化**：同意、驳回、退回（到选的节点）、转办、委托、加签减签（前加签、后加签、并行）、撤回这一步、释放回收件箱、
   指定承办人、催办、抄送、留言……每个动作是一个插件：谁能做、要填什么（zod schema）、做了什么、界面上叫什么。
   待办详情直接给出“这个人现在能做的动作”和要填的字段，前端按它渲染按钮与对话框——加新动作不用改引擎和页面，流程代码也能定义自己的动作。
2. **候选人用 text[] + GIN**（替换候选人表）：每条待办一列标记 `user:…`、`role:…`、`dept:…`；查待办是
   `candidates && 我的标记`（身份展开成自己、角色、所在部门及上级部门），走索引不连表；改派、加签只改这一列。
3. **单据与业务表绑定**：form 可以绑定一个 ORM 实体——发起时写业务表，按环节权限改字段，结束时监听回写状态；单据与流程同一事务。
4. **补齐能力**：草稿、发起视图、委托与休假代理、加签减签、撤回这一步、释放、指定承办人、批量认领与处理、改单据数据（留前后值）、
   票签与权重、提级、调用流程的 forEach 与异步、自定义节点类型、实例迁移到新版本。
5. **事件与通知**：发件箱表保证投递，NOTIFY 推实时；通知渠道可插拔（站内、邮件、IM），模板在流程代码里写。
6. **组织模型**：默认实现建在 ORM 实体上（公司、部门树、岗位、员工、上级），处理人解析器开箱可用；也可以换成宿主自己的。
7. **测试**：Java 版的场景里语义一致的保留为回归；其余改写成 TS 的场景测试（类型检查过的“谁做了什么、期望什么”），流程工作室里也能跑。

## D. 表单模块（这一轮做全）

- 字段：文字、数字、金额（Decimal）、日期 / 时间 / 区间、选择（固定选项、字典、远程搜索）、人员与部门、附件、地区、
  明细表（行内编辑、合计行、导入）、计算字段（TS 表达式）、联动（选了 A 才出现 B、B 的选项跟着 A 变）。
- 规则：显示、必填、能改的条件；zod 校验；跨字段校验；按环节的权限矩阵（字段 × 环节一张表格编辑）。
- 布局：分组、栏数、页签、手机布局；打印视图。
- 设计：表单设计器（拖字段、改属性、实时预览）与代码（form.ts）是同一份；也可以整页写 TSX。
- 运行：建在组件库的 SchemaForm 上——明细表、条件、计算字段、字典等补进组件库（所有使用方受益），流程只是用它。
- 字典与选项来源：宿主登记（静态、ORM 查询、接口），表单里按名字引用。

## E. 流程工作室（管理员在线编写）

- 流程列表（分类、启停、版本、负责人）；新建从模板或空白开始。
- 编辑：图（设计器）、表单（设计器 + 预览）、权限矩阵、代码（文件树 + CodeEditor + TS 语言服务：类型、补全、报错、跳转定义；
  语言服务放在 Web Worker 里、用到才加载）、场景测试、和任意版本对比（图、表单、代码三种对比）。
- 发布：类型检查与校验都过才能发；发布说明；回滚；把运行中的实例迁到新版本（预览迁移的影响）。
- 宿主模块：工作室里能看到可以 import 的模块与它们的类型（宿主登记时生成声明文件）。
- 编译与加载：服务端用 TS 做类型检查、去类型后执行；浏览器在 Worker 里编译；按版本缓存编译结果。

## F. 文档站的“流程中心”演示（flow-demo 删掉，全部搬到这里）

- 浏览器里 PGlite + 引擎 + 业务库；数据存 IndexedDB，刷新不丢，可重置；顶栏切换演示身份；“时钟快进”演示超时、提醒、定时作业；
  首次打开按需加载，带进度。
- 业务模型（参考 easy-query-ts 的 Company / Department / User / Product / Order，换成审批场景）：组织（公司、部门树、岗位、员工、上级）、
  供应商、物料、成本中心与预算、字典；单据：请假、出差与报销（明细、发票）、采购（物料明细、供应商）、付款（推 ERP 的异步动作）、
  合同（并行会签、子流程）。种子含几十名员工与历史实例（已完成、进行中、超时、异常、委托中、加签中）。
- 页面：
  - 工作台：待办、已办、抄送、我发起的、委托给我的、草稿；筛选、搜索、批量处理；实时更新（NOTIFY）。
  - 发起中心：分类、搜索、常用；按表单发起，草稿。
  - 审批单：表单（按环节权限）、进度图、时间线、留言与 @ 提及、附件、打印；动作栏按插件渲染。
  - 我的单据：按业务看单据与状态。
  - 流程工作室（E）。
  - 管理：实例搜索与干预（暂停、终止、跳转、改派、迁移版本）、作业与异常、委托与休假代理、组织与字典。
  - 监控：积压、平均耗时、超时率、瓶颈环节（在流程图上着色）、各流程趋势图。
  - 个人设置：代理、通知偏好。
- 服务端部署：文档写“kit + PG”的接法（同一套页面经 kit 的 action 调用），引擎在 PG 17 容器上的测试与一个 kit 集成测试守住服务端这条路。
- flow-demo 的端到端覆盖先搬成文档站的浏览器测试，再删 flow-demo，不让测试覆盖倒退。
