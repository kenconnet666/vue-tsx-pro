  任务摘要列出变了的示例；只报告不失败，这次的截图成为下一次的基线。每次推送后看摘要：变了的是不是有意的。

### P0.2 box-sizing 统一

- 现状：约 80 个文件写了内边距或边框却没设 `box-sizing`（日期、Tree、Descriptions、Empty、Stat、CalendarView……），使用方写的宽高含不含
  内边距因组件而异。CSharpUi 报的例子：Listbox 写 `height: 16rem`，实际是 16rem + 0.5em。
- 做法：样式引擎最低的层里加一条 `:where([data-part]) { box-sizing: border-box }`（只管库的部件，不碰使用方的元素；
  使用方的样式照样盖过它）。各组件里零散的 `boxSizing: 'border-box'` 删掉。24.1 给内部节点补 `data-part` 后自然覆盖。
- 靠 P0.1 的截图兜底，逐个看尺寸有变化的示例。改完通知 CSharpUi 重截对照。
- 范围用 `[data-part]`（用户定）：`[data-scope]` 会连组件里使用方放进来的内容一起改。

### P0.3 焦点环被裁的检查

Blazor 报的 CodeBlock“展开全部”（外框 overflow: hidden 把画在外侧的焦点环整圈裁掉）是一类问题：表格格子、卡片、滚动区域里的按钮都可能。
文档站示例的浏览器测试（demos.browser.test.ts）加一项：逐个用键盘聚焦可聚焦的元素，按 outline 的宽度与偏移算出焦点环的范围，
检查它没有被任何 overflow 不是 visible 的祖先裁掉；被裁的改用 `focusRingStyles.inset`（画在里面）。

## P1 小而急

- **P1.1 CSP nonce**：运行时样式往 `<style>` 里插规则，严格 CSP（style-src 不带 `unsafe-inline`）的站点上会被拦。
  STYLE-ENGINE.md 写了要借 nonce，源码没实现。`createUi({ nonce })` 与服务端渲染收集样式时都带上；文档站加一节、加测试（CSP 头下页面有样式）。
- **P1.2 ErrorBoundary**：一块内容出错不让整页白掉：出错时显示 Result 占位（可重试、可展开错误详情），`onError` 交给应用上报。
  演练场里已有一个私有实现，抽成公共组件，演练场改用它。
- **P1.3 文档站与 npm 的差距**：文档站从 master 部署，npm 上是最近一次发布的版本，两次发版之间文档会先出现还没发布的新写法。
  原想法是正式站按发版的标签部署、master 另部署一个预览站。按“不写具体版本、一律用最新版”的定法改为：不建预览站，文档照旧跟 master，
  靠 P7 让发版变成随手的事（每批做完就发），差距只有几小时；安装命令不写版本号。
- **P1.0 下游报来的问题（先修，不等审阅）**：
  - 样式引擎：`priority.ts` 的伪类表写成驼峰键（`':focusVisible'`、`':focusWithin'`），而生成的选择器是 `:focus-visible`、`:focus-within`，
    查表落空回到默认 40，排在 `:hover`（130）前面——悬停会盖掉键盘焦点样式（ResizeHandle、列宽手柄……所有同时写了悬停与焦点的样式）。Blazor 报告。
  - DateField / DateRangePicker：点第 2 段起的段，外壳的 `focusOnShell` 把它当成点在空白处，焦点被抢到第一段（点“月”再输数字改的是“年”）。
    “点在组里”的判断要用整组而不是第一段。Blazor 报告。
  - CodeBlock“展开全部”的焦点环被外框的 overflow: hidden 裁掉，键盘聚焦时看不见。Blazor 报告；同类问题见 P0.3。
- **P1.4 过时文档**：ROADMAP“已知局限”还写着表格没有单元格方向键导航，实际 DataTable 的 `cellNavigation` 已经做了；随手改掉。

### P2.3 逐页的样式与内容问题

巡检（`pnpm docs:review`，136 页 446 个示例，亮色桌面）的自动检查——控制台报错、横向溢出、两列不齐——都是零；下面是逐页看总览图找到的。

**共性问题**（逐页改之前先在基础层解决）：

- **卡片网格落单**：4 张卡排成 3 + 1（Stat 基础用法、Stat 数值变化、Card 样式），6 张排成 4 + 2（Flex 自动换列）。
  Grid 的 `minItemWidth` 在示例宽度下凑出 3 列。改法：这类“一排指标”用 StatGroup 或固定列数；Grid 考虑加“列数只取能整除项数的”选项（待评估）。
- **列表里的标题、操作写成下划线链接**：ItemList 待办、Stat 一排指标的“去处理”、Card 页头的“全部超时”、Descriptions 的物流单号、
  Timeline 的附件，一列下来下划线很重。正文链接要下划线（WCAG 1.4.1），界面里的导航链接按 Text 页说的用 `underline="hover"`；
  这几个组件里的链接部件默认就该是 hover 下划线。
- **示例里套示例卡片**：Code 页“示例卡片”演示 CodePreview，看不出哪个是演示——挪到文档工具页后重写。

**逐页**：

- Button：并入 IconButton 后，“尺寸”里已有一排图标按钮，IconButton 的“基础用法”合进“尺寸”“样式”两节，不再单列工具栏示例。
- IconButton“预设按钮”：ClearButton 单独放在输入框外面，不是真实用法——改成 TextField 的 `clearable` 里看到它，预设按钮只列出名称与读屏文字。
- IconButton“加载、不可用与异步复制”：三行文字说明 + 小按钮，信息密度低；并入 Button 页“加载中”“不可用”两节。
- ButtonBase“不可用与加载中”：加载中那一项看不出在加载（没有指示）。“自定义外观的按钮”演示的是可选中的卡片 → 改用 P3.1 ChoiceCard，
  ButtonBase 页改演示真正“长得不像按钮的按钮”（可点的行、可展开的标题）。
- Text“截断与换行”：三张卡排成 2 + 1。
- Icon“自定义图标”：只有三个图标，太空；补一个“在按钮、菜单里用自己的图标”。
- Code“行内代码”：一行文字，上下大片留白；与“文案里的行内代码”合成一节。“一组代码”放了两组一模一样的代码块（演示联动），看起来像重复——
  改成两组内容不同（安装命令 + 引入代码）、同一个 `_value` 联动。
- Flex“伸展、行内与行列间距”：文件按钮一排 3 个排成两行，像表格又不是表格，换成 GridList 的真实场景。
- ScrollArea“两个方向”：原生 table 手写粘性表头 → Table（P2.2）；“纵向滚动”的消息列表 → ItemList。
- Splitter“上下排列”：上栏是原生 textarea 风格，预览是纯文字，像未完成的界面 → 上栏用 Textarea / CodeEditor，下栏用 Prose 渲染。
- Card“样式”：ghost 单独落在第二行，看不出它“没有边框与底色”——四种样式放在同一个有底色的舞台上一排对比。
- Stat“基础用法”“数值变化”：3 + 1 落单（见共性）；“数值变化”手画趋势柱 → Sparkline（P2.2）。
- ProportionBar：图例两端对齐，中间那项悬在中间，和左右两项对不上 → 图例从起始边依次排开。
- ItemList：StatusDot 挪去 Badge 页后这页只剩一个示例，补“可选中的行”（P3.2）、“通知列表”两个示例。
- Tree“按需加载”“勾选”：树写死高度（16–17rem），节点少时下面一大片空白。Tree 始终虚拟滚动、要有高度——加 `maxHeight`
  式的自动高度（内容少时按内容高、多了才滚动），组件层补，不在示例里调高度。VirtualList、Listbox 同理检查。
- DateTime“倒计时”：四张卡排成 3 + 1（共性问题）；“相对时间”用原生 ul / li → ItemList（P2.2）。

## P4 按 schema 生成表单（第一步）

- `SchemaForm`：传 zod schema，按类型选控件（字符串 → TextField、枚举 → Select、数字 → NumberField、布尔 → Switch、日期 → DatePicker、
  枚举数组 → 多选、嵌套对象 → FormSection、对象数组 → 可增删的行）；标签、单位、占位、栏宽写在 `.meta()`；校验、必填、长度、范围
  沿用 useForm 与 form-constraints。
- 局部替换：`fields={{ category: () => <Cascader … /> }}`；也能放在手写的 `<Form>` 里只生成一部分字段。布局：`columns`、按 meta 分组。
- QueryTable / FilterBar 的查询条件可以用同一套字段描述生成（现在是渲染函数手写）。
- 第二步（以后）：JSON 字段配置（设计器、后端下发）在运行时转成 zod；显示 / 必填条件用 ConditionBuilder 的条件 JSON。
- 完成标准：文档站“供应商准入”示例能用 SchemaForm 重写成十几行；类型测试保证 `fields` 的键与 schema 一致。

## P12 层层合并、层层转发，复用基础组件，去掉重复（用户 2026-11-07 加）

做组件库的基本要求，贯穿 P2.5 与之后所有组件改动：

- **属性层层合并、层层转发，上层覆盖下层**：使用方写的 > 组合组件给的 > 基础组件的默认。没声明的属性落到根元素（mergeAttrs），
  部件属性（`propsXxx`）用 mergePartProps 合并；组合组件把里面每个基础组件的部件属性都转发出去（Select → Listbox → 选项、
  QueryTable → DataTable → 单元格……），使用方不用绕过组件就能改到任何一层。
- **上层组件用好基础设施与基础组件**：组件里手写的节点能换成基础组件的换（按钮 → ButtonBase / IconButton、链接 → Link、
  图标 → Icon、计数 → Badge、时间 → RelativeTime / DateTime、空状态 → Empty、加载 → Spinner、头像 → Avatar、键位 → Kbd……）；
  焦点环、色调、尺寸档、动效用共用的样式与工具。
- **每个部件都带标记**：`data-scope` / `data-part`。现在只有用带名字配方的组件有（下游 2026-11-07 报：Listbox 的根没有，
  `:where([data-part])` 的 border-box 罩不到，写 16rem 高实际多出上下内边距）。用 `css.create` 的组件逐个补上
  `partAttrs`（Listbox 的根先补了），最好随 P5 改成带名字的配方；补完后用浏览器测试扫一遍“写的宽高就是实际宽高”。
  参考 Blazor 版（Rune）：部件节点都经 `Part.Of` / `Recipe.Of` 生成，生成时就带标记，从根上不会漏——我们也应让“取部件样式”
  与“打部件标记”是同一个调用，而不是各组件自己记得加。
- **用得多的抽出来**：同一种节点的样式或行为出现第三次就抽成组件或工具。
- **同一件事只留一份**：差不多的实现合并，命名、属性、外观保持一致（这次的例子：CommentThread、NotificationCenter 各自手写相对时间，
  改用 RelativeTime；flow 的流程图与画布两份，见 P11）。
- 做法：先写检查脚本列出候选（非 base 目录里手写的 `<button>`、`<a>`、`<time>`、内联 `<svg>` 图标、`format.relative`、
  没转发的内部组件部件属性……），结果记进本文件，逐个组件过；能固定成规则的进 `pnpm check`。
- 顺手发现的问题照修，提交里写清；影响部件、token、语言包的通知下游。
