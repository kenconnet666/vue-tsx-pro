# 0010 通知、广播、代理与监控

第 7 批（ROADMAP 26.7）：流程推进时谁该知道、多实例部署时页面怎么实时刷新、休假时待办交给谁、管理员看什么。

## 1. 通知：站内信箱兼发件箱

- 一张表 `flow_notification`：`readAt` 是收件人读过（站内信箱），`sentAt` 是外部投递送到了（发件箱）。
  在推进的同一个事务里写入——提交了才有通知，回滚了就没有，不会发出一条单子里并不存在的消息（发件箱模式）。
- 按这一步的流转记录生成（`runtime/notifications.ts`）：

  | 事件                   | 来自                                | 发给                             |
  | ---------------------- | ----------------------------------- | -------------------------------- |
  | `arrived` / `returned` | 新建的待办（退回来的是 `returned`） | 处理人；收件箱里的发给能认领的人 |
  | `reminded`             | 手动催办、收件箱很久没人认领        | 同上                             |
  | `dueSoon`              | 到期前的提醒                        | 同上                             |
  | `overdue`              | 待办超时                            | 同上                             |
  | `cc`                   | 抄送                                | 抄送的人                         |
  | `finished`             | 实例结束（完成、终止、撤回）        | 发起人                           |

  流程级、节点级的 `notify`（模型包早就有的设置）：`false` 不发；`to` 加收件人（同处理人的写法）；`template` 换文字。
  不发给引起这件事的人自己。

- 引擎只存事件、当时的标题与环节名、谁引起的；文案由界面按事件拼（语言包），配了模板时 `message` 是渲染好的文字。
- 外部投递：引擎选项 `notifications.deliver`。提交后逐条送；抛错的记下原因留着，`jobs.runDue` 顺带再试，最多 5 次。
  多实例部署时先带条件地占用（次数加一）再投递，同一条不会被两个进程各送一次。
- 接口：`engine.notifications.list / unread / read`，客户端同名；页面顶栏的铃铛按它列出、点一条去那张单。
