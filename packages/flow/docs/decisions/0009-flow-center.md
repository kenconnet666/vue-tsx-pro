# 0009 文档站的流程中心（2026-11-08）

流程引擎在浏览器里完整地跑起来，给人看、给人用：工作台、发起、审批单、我的单据、管理。它同时是引擎的验收——
页面只经下面的客户端用引擎，同一套页面接到服务端（kit + PG）时不改。参考了 flow-demo、Java 版的前端与钉钉 / 飞书审批的交互，
下面写的是比它们做得好的地方与取舍。

## 1. 形态

- 独立的应用，不是文档里的一个示例：路由 `/flow/*`，全屏的应用外壳（AppShell：侧栏、顶栏的演示身份与时钟）。
  代码在 `apps/docs/src/flow-center/`，按职责分文件夹（`runtime/` 运行时、`domain/` 业务模型与种子、`processes/` 流程工程、
  `pages/` 页面、`parts/` 页面共用的组合）。文档的“流程引擎”“流程设计与审批”两页链接过来。
- 引擎跑在 Web Worker 里：PGlite（数据存 IndexedDB，刷新不丢）、引擎、业务库都在 Worker，主线程只渲染，推进流程、跑作业不卡界面。
  第一次打开时建表、发布流程、写种子，带进度；“重置演示数据”删库重来。

## 2. 客户端：已登录的人看到的引擎

Java 版的前端另写一层 REST 接口与 DTO，flow-demo 的页面直接拿着 actor 调引擎。这里换成：

- `FlowClient`（引擎包的 `./client`）：命令与查询都不带 actor——“我”的待办、“我”发起、以“我”的身份处理。是谁由连接的那一头定：
  浏览器里是顶栏切换的演示身份，服务端是会话。页面代码因此不碰身份，也就不会被伪造。
- `flowEndpoint(engine, { actor })`：服务那一头，按方法名分到引擎的命令与查询（白名单），注入 actor；
  值用 json-wire 编解码（Decimal、日期、时刻原样还原），错误带着 `code` 与 `details` 还原成 FlowError。
- 传输可换：Worker 的消息端口（`portTransport` / `servePort`，演示用），HTTP（kit 的 action，服务端部署）。
  命令成功后端点广播“数据变了”，列表、计数实时刷新（服务端那条路在第 7 批接 NOTIFY）。

## 3. 组织与业务模型

- 组织（公司、部门树、岗位、员工、上级）、供应商、物料、成本中心与预算、字典都是 easy-query 的实体，与引擎同一个库。
  引擎的 `org`（角色、部门展开成人，收件箱的负责人）与处理人解析器（上级、部门负责人）建在这些实体上。
  组织这部分做成引擎包的 `./org`（组织目录），接入方没有自己的组织库时直接用，有 HR 系统时整批 `sync()` 进来：
  - 编号是文字（工号、部门编码），与 Actor.id 一一对应；离职的不删，active 置否，历史里的名字还在；
  - 引擎在事务里展开处理人，读内存里的快照而不另发查询——组织小、少变，省掉往返，也不会在只有一条连接的 PGlite 上等自己的事务；
    绕过目录改了表、或别的进程改了，调 `refresh()`；
  - Actor 的部门是所在部门连同全部上级部门：`members({ department })` 含下级部门，收件箱的可见范围与它一致；
  - 解析器的参数：`manager` 的 `levels`（隔级上级）、`departmentHead` 的 `level`（第几级部门，1 是一级部门）、两者的 `field`
    （按单据里的某个人算，默认发起人）；离职、空缺、是自己时往上找。
- 单据：请假、出差与报销（明细、发票）、采购（物料明细、供应商）、付款（推 ERP 的异步动作，会失败进异常）、
  合同（并行会签、调用子流程）。每个流程写成 TS 工程（`form.ts` 的清单、`logic.ts` 的逻辑、`process.json` 的图），
  在 Worker 里编译发布——流程即 TS 工程就在眼前。
- 种子：几十名员工；历史实例覆盖已完成、进行中、超时、异常、委托中、加签中。时间按演示的时钟往前推着生成。

## 4. 页面（比照钉钉 / 飞书，做得更顺手的地方）

- 工作台：待办、已办、抄送我的、我发起的、委托给我的、草稿在一个列表里切换；左列表右详情（像邮件），不用来回换页；
  超时、快到期的排前面并标出来；键盘上下、回车处理；勾选后批量同意（逐条给出结果，失败的留在列表里）；数据变了自动刷新。
- 审批单：
  - 单据按这一步的权限渲染（flow-ts-ui 的 useFlowForm），只读的人看到 SchemaView；
  - 提交前就看到“提交后到哪、谁处理”（待办详情的 next），要上一步选人的当场选（picks），退回能退到哪、退给谁一目了然；
  - 进度图标出走过的、正在处理的、出错的；时间线里改过的数据写出前后值；
  - 动作栏按待办的 operations 渲染：认领、转办、委托、加签……新加一个动作插件，页面不用改。
- 发起中心：分类、搜索、常用；发起页同样预测下一步、选人；草稿自动存。
- 我的单据、管理（实例干预、作业与异常、委托代理、组织与字典）、时钟快进（演示超时、提醒、定时作业）。

## 5. 分步

1. 客户端与端点（引擎包 `./client`）；Worker 运行时（PGlite + IndexedDB、演示身份、时钟、重置）；组织与业务模型、流程工程、种子；应用外壳。
2. 工作台、审批单、发起中心。
3. 我的单据、管理页、时钟快进。
4. flow-demo 的端到端覆盖搬成文档站的浏览器测试，删 flow-demo；“kit + PG”的接法写进文档，加一个 kit 集成测试。
