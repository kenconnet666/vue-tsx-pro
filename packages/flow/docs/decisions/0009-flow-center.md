# 0009 文档站的流程中心

流程引擎在浏览器里完整地跑起来，给人看、给人用；它同时是引擎的验收——页面只经客户端用引擎，接到服务端（kit + PG）时不改。
交互参考了 Java 版的前端与钉钉 / 飞书审批。

## 1. 形态

- 独立的应用：路由 `/flow/*`，全屏的应用外壳（侧栏导航；顶栏是演示身份、通知铃铛、演示时钟、重置）。
  代码在 `apps/docs/src/flow-center/`：`runtime/`（Worker、后端、页面这头的状态）、`domain/`（组织、业务库、种子、单据的数据来源）、
  `processes/`（演示的流程，合同是流程工程）、`pages/`、`parts/`（页面共用的组合）、`studio/`（工作室与语言服务）。
- 引擎跑在 Web Worker 里：PGlite（存 IndexedDB，刷新不丢）、引擎、组织目录、业务库都在 Worker，主线程只渲染。
  第一次打开时建表、发布流程、写种子，带进度；库带结构版本，老结构的库自动删了重建；“重置”删库重来。

## 2. 客户端：已登录的人看到的引擎

- `FlowClient`（`./client`）：命令与查询都不带 actor，“我”是谁由连接的那一头定（浏览器里是演示身份，服务端是会话），页面伪造不了。
- `flowEndpoint(engine, { actor })`：方法白名单，注入 actor；参数与值用 json-wire 编解码，两头同一个 reader（时刻还原成 `Date`）；
  错误带 `code` 与 `details` 还原成 FlowError。
- 传输可换：Worker 的消息端口（`portTransport` / `servePort`）、HTTP（`flowHttpHandler` / `httpTransport`，Web 标准的 Request / Response）。
- 数据变了：端点自己的改动，加上引擎随提交的广播（0010 第 2 节）；页面把同一次改动的两下合成一次刷新。

## 3. 组织与业务

- 组织做成引擎包的 `./org`（组织目录）：部门、角色、员工的表，有 HR 系统时整批 `sync()`；编号是文字，与 Actor.id 一一对应；
  离职的不删、置否。引擎在事务里展开处理人，读内存快照而不另发查询（PGlite 只有一条连接，另开查询会等自己的事务）。
  解析器：`manager`（`levels` 隔级）、`departmentHead`（`level` 第几级部门），按 `field` 指的人算，离职、空缺、是自己时往上找。
- 业务库（供应商、物料、成本中心与预算）是同一个库里的 easy-query 实体，登记成宿主模块 `@app/business`：流程代码直接 import
  （合同的守卫查相对方有没有停用），声明给工作室的编辑器；同样读快照。
- 单据：请假、出差报销、采购、付款（推 ERP 的异步动作，会失败进异常）、合同（流程工程：并行会审、按付款计划调用付款）。
  种子覆盖已完成、进行中、超时、异常、委托中、加签中，时间按演示时钟往前推着生成。

## 4. 页面

- 工作台：整宽的表格，上面的页签筛待办、已办、抄送我的、我发起的、草稿（带待办数、未读抄送数），再按关键字、流程筛；
  点一行在抽屉里开审批单，J / K 换一条，处理完自动换到下一条。超时、快到期的排前面；勾选后批量同意（逐条给结果，失败的留着勾上）、
  抄送批量已读。左列表右详情、顶栏放格子都试过：列表挤、离表格远，批量不顺手。
- 通知铃铛按时间列“发生了什么”，不按格子分类（不与页签重复）。
- 审批单：单据按这一步的权限渲染；提交前看到“之后到哪、谁处理”，要选人的当场选，退回能退到哪一目了然；进度图、流转记录；
  动作栏按待办的 operations 渲染；管理员的干预（暂停、终止、跳转、改派、改数据）。
- 发起中心与发起页（预测下一步、草稿）、单据（我经手的、我发起的、全部）、代理、监控（管理员）、管理（异常、组织）。
- 工作室（管理员）：图、单据、代码（TS 7 的语言服务在 Worker 里）、测试（`test.ts` 的场景）、试运行、版本（对比、载入、回滚、迁移）。

端到端覆盖是 `flow-center.browser.test.ts`（Chromium）：审批、备案、通知、工作室发布、单据页。
