# TS：IBM Db2 方言

```ts
import ibmdb from 'ibm_db';
import { db2 } from '@zerodep-dev/easy-query-ts-db2';

const url = 'DATABASE=eqts;HOSTNAME=host;PORT=50000;PROTOCOL=TCPIP;UID=db2inst1;PWD=…';
const db = createDb({ schema, adapter: db2(new ibmdb.Pool(), url) });
```

驱动用 IBM 的 `ibm_db`（ODBC，需要 IBM CLI 驱动）。仓库里 `ibm_db` 的安装脚本默认不运行（要下载上百 MB），跑 Db2 实库测试前执行
`pnpm --filter @zerodep-dev/easy-query-ts-db2 driver`。实测环境是 Linux：Windows 上 ibm_db 4.1 + Node 24 建不出 CLI 环境
（`CLI0600E`，`db2cli install -setup` 之后 `db2cli` 本身能用，Node 的绑定仍然不行），本机用 WSL 里的 Linux 容器跑。

## 写法

- 双引号、参数 `?`、`OFFSET … FETCH NEXT … ROWS ONLY`；upsert 写成 `MERGE … USING (VALUES …)`。
- 自增列 `GENERATED BY DEFAULT AS IDENTITY`，插入后在同一条连接上取 `IDENTITY_VAL_LOCAL()`；写入走预处理语句，拿到影响的行数。
- 字符串列 `VARCHAR(n CODEUNITS32)`：长度按字符算（默认按字节，中文一个字 3 个字节）；`length` / `substring` 也按字符。
- `CASE` 的分支、选出的值里的参数按列的类型 `CAST`（Db2 推不出无类型参数的类型，SQL0418N）。
- 没有条件的更新、删除补 `WHERE 1 = 1`（否则有"改动整张表"的警告 SQL0513W）；驱动把 SQLSTATE `01xxx` 的警告当错误，这里一律当成功。
- 子查询里的 `WITH` 提到语句开头；递归 CTE 不写 `RECURSIVE`，递归成员里不能有显式 join：内连接改成逗号连接、`ON` 的条件挪进 `WHERE`。
- 日期：`+ n DAYS` / `MONTHS`、`DAYS()` 相减、`TRUNC_TIMESTAMP`；`dateFormat` 把各部分的 `VARCHAR_FORMAT` 与文字拼起来（格式里不能夹文字）。
- 行锁：`FOR UPDATE WITH RS`、`SKIP LOCKED DATA`；没有 `NOWAIT`（报错）。保存点 `SAVEPOINT … ON ROLLBACK RETAIN CURSORS`。
- JSON：`JSON_VALUE` / `JSON_QUERY` / `JSON_EXISTS`；`jsonLength` 报不支持（`JSON_TABLE` 只能从根展开、没有 `NESTED`）。
- 建表与读库结构：`SYSCAT.TABLES` / `COLUMNS` / `INDEXES` / `REFERENCES`；`CREATE INDEX` 没有 `IF NOT EXISTS`；改表名 `RENAME TABLE`。

实测：Db2 12.1.2（`icr.io/db2_community/db2`）共用套件 124 个用例；CI 单独一个 runner。
